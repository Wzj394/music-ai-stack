# 怎么用这个仓库

## 这个仓库是干什么的

一句话：**把音乐 AI 这个领域的「地图」画出来，并且标清楚我走到哪了。**

不是教程搬运站，也不是工具收藏夹。它的用途有三个：

1. **查** —— 想做某件事（比如"把一段人声转成 MIDI"），能快速知道该用哪个工具、从哪开始
2. **记** —— 试过的、踩过的坑、跑通的参数，写进 `notes/`
3. **看进度** —— 一眼看出自己在这个地图上走到哪了

## 三条使用规则

### 1. 先看 `docs/08-学习路径.md`，别从工具表开始

工具表有几百行，一上来就看会淹死。学习路径那篇是按"你现在会什么"排的顺序。

### 2. 每个条目都有「状态」，别踩死项目

文档里的工具会标：

| 标记 | 意思 |
|---|---|
| 🟢 活跃 | 还在更新，可以放心用 |
| 🟡 放缓 | 能用，但别指望新功能 |
| 🔴 停更 / 归档 | 能跑，但不建议新项目用 |
| ⚪ 被取代 | 有更好的替代品，文档里会写是哪个 |

**开源项目死掉是常态**，尤其 AI 领域。看到一个 2023 年的教程推荐某个模型，先去 GitHub 看最后一次提交是什么时候。

### 3. 试过的东西写进 `notes/`

看过的文档会忘，自己跑通一遍的东西记得住。

`notes/` 里一篇笔记一个文件，命名用 `日期-主题.md`，比如：

```
notes/
├── 2026-10-12-demucs分离人声初体验.md
├── 2026-10-15-reaper跑python脚本踩坑.md
└── 2026-10-20-whisper转写中文歌词.md
```

模板在 `notes/_模板.md`，直接复制改名就能用。

## 怎么参与（如果以后有人一起）

- 发现链接失效、项目停更、有更好的替代品 → 开 Issue 或直接提 PR
- 想加自己的笔记 → 放 `notes/` 下，用同样命名规则

## 关于准确性

这个仓库里的信息：

- **工具的链接、维护状态** —— 写的时候核实过，但会过期。发现不对请提 Issue
- **我自己的笔记** —— 个人经验，可能有错，以官方文档为准
- **学习路径建议** —— 主观意见，不是唯一答案
