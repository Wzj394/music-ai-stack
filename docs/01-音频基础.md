# 01 · 音频基础（AI 视角）

> 这篇不讲"什么是声音"——你比我懂。
> 只讲一件事：**在 DAW 里天天见的概念，到了 AI 里会变成什么样子、哪里会坑到你。**

## 为什么单独写一篇

搞音乐的人上手音频 AI，最容易栽的不是模型，是**数据格式**。你脑子里想的是"这段音频"，模型看到的是一个形状为 `[1, 16000]` 的浮点数组。中间这层转换出错，表现往往是"模型没报错，但结果全是噪声"——非常难 debug。

所以先把这层搞清楚。

---

## 一、采样率：AI 里通常不是 44.1k / 48k

你工作流里默认 44.1k 或 48k。但模型基本不用这些：

| 采样率 | 常见用途 | 为什么是这个数 |
|---|---|---|
| **16 kHz** | 语音识别（ASR）、人声活动检测（VAD） | 语音主要能量在 8k 以下，16k 够用，数据量只有 48k 的三分之一 |
| **22.05 / 24 kHz** | 音频生成模型（如 MusicGen 系列） | 兼顾质量与算力 |
| **32 kHz** | 部分声源分离、高质量语音 | |
| **44.1 / 48 kHz** | 高质量音乐生成（如 Stable Audio 系列） | 音乐要保留高频泛音 |

**坑在哪**：你拿 48k 的成品直接喂给要 16k 的模型，它**不会报错**——它会当成 16k 来处理。结果就是**所有音高变成原来的 1/3**，听起来像慢放加沉闷。

反过来，16k 喂给要 48k 的模型，会变成快放 3 倍。

> **记一条**：喂模型前永远先确认模型要的采样率，然后显式重采样。**不要相信"它会自己处理"。**

```python
import librosa

y, sr = librosa.load("input.wav", sr=16000, mono=True)  # 显式指定 sr，librosa 会帮你重采样
```

---

## 二、位深和浮点：训练时用的是 float32

- DAW 里你常见 16bit / 24bit 整数
- 模型里一律转成 **float32**，取值范围通常是 **[-1.0, 1.0]**

转换时常见的两个错误：

| 错误 | 后果 |
|---|---|
| 忘了除以 32768（16bit 最大值） | 数值范围变成 ±32768，模型输入爆炸，输出全是噪声或直接 NaN |
| 归一化到 [-1,1] 后又做了响度标准化 | 动态被压扁，模型学到错误的电平关系 |

```python
import soundfile as sf

x, sr = sf.read("input.wav", dtype="float32")   # soundfile 会自己做好转换
print(x.min(), x.max())   # 应该在 -1.0 ~ 1.0 之间
```

**顺手检查电平**，这是排查"输出全是噪声"的第一步。

---

## 三、声道：单声道是常态

大部分模型只吃单声道。

- 立体声 → 单声道：直接取平均 `(L+R)/2`，注意可能相位抵消
- 单声道 → 立体声：不要简单复制两份（那不是真的立体声，只是双单声道）

```python
if x.ndim > 1:
    x = x.mean(axis=1)     # 转单声道
```

## 四、时频表示：AI 音频的核心

这是**最关键的一节**。

波形（时域）对模型很不友好——直接处理 48000 个采样点太长了。所以几乎所有音频模型都工作在**时频域**：把音频切成小段，每段做 FFT，得到一张"时间 × 频率"的图（频谱图）。

### STFT 的三个参数

| 参数 | 含义 | 常见值 |
|---|---|---|
| `n_fft` / window size | 每次 FFT 用多少采样点 | 1024 / 2048 |
| `hop_length` | 相邻两帧间隔多少采样点 | `n_fft / 4`（即 256 / 512） |
| `win_length` | 窗函数长度，通常等于 `n_fft` | 同上 |

**这三个数一改，频谱图的形状就变了**，而模型的输入尺寸是固定的——对不上就会报错或结果错乱。

```python
import torch
import torchaudio

spec = torchaudio.transforms.Spectrogram(
    n_fft=2048,
    hop_length=512,
    power=2.0,          # 2.0 = 功率谱，1.0 = 幅度谱
)
S = spec(waveform)      # [freq_bins, time_frames]
```

`freq_bins = n_fft / 2 + 1`，所以 `n_fft=2048` → 1025 个频点。

### 为什么用 Mel

人耳对频率的感知不是线性的——100Hz 和 200Hz 的差别，你听得出来；10000Hz 和 10100Hz 的差别，你基本听不出来。

**Mel 刻度就是把频率轴按人耳感知重新压一遍**，低频给更多分辨率，高频压缩。

```python
mel = torchaudio.transforms.MelSpectrogram(
    sample_rate=16000,
    n_fft=400,
    hop_length=160,
    n_mels=80,          # 80 或 128 是最常见的
)
```

**80 维 log-Mel** 是语音识别领域二十年的标准输入，你会在无数论文和代码里看到。

### 为什么要取 log

声音的响度感知也是对数的（dB）。直接拿功率谱，动态范围太大，模型不好学。

```
log_mel = log(mel + 1e-6)   # 加个小常数防止 log(0)
```

## 五、张量形状：最容易搞混的地方

同样一段音频，不同库、不同模型的期望形状可能完全不同：

| 形状 | 含义 | 谁用 |
|---|---|---|
| `[samples]` | 纯一维波形 | 简单处理 |
| `[channels, samples]` | 声道在前 | torchaudio 传统 |
| `[batch, channels, samples]` | 批量的标准波形格式 | 大多数 PyTorch 模型 |
| `[batch, time, freq]` | 时频图（时间在前） | 一些 Transformer 模型 |
| `[batch, freq, time]` | 时频图（频率在前） | librosa / 传统 CNN |

**`[time, freq]` 还是 `[freq, time]`，是这类项目里最高频的低级错误。**

> 排查口诀：**打印形状，对照模型文档，别靠猜。**

```python
print(x.shape)   # 养成习惯
```

## 六、响度：训练和推理的一个隐形变量

- **训练时**数据集通常做过响度标准化
- **推理时**你喂进去的音频如果电平差很多，输出质量会明显下降

音乐制作里你熟悉 **LUFS**，AI 这边也吃这一套。

```python
import pyloudnorm as pyln
meter = pyln.Meter(sr)
loudness = meter.integrated_loudness(x)
x_norm = pyln.normalize.loudness(x, loudness, -23.0)   # 归到 -23 LUFS
```

**实战经验**：模型输出听起来"闷"、"糊"、"破"，先别怀疑模型，先看电平。

---

## 七、时长：模型都有上限

- Whisper 类模型通常按 30 秒窗口处理
- 很多生成模型训练时就固定了几秒到几十秒

**长音频要自己切片**，切完还要处理边界（交叉淡入淡出、overlap）。

```python
# 简单的定长切片
chunk = 30 * sr
for i in range(0, len(x), chunk):
    yield x[i : i + chunk]
```

**坑**：硬切会在边界产生咔哒声，而且模型在片段边界处上下文缺失，转写/分离结果容易在接缝处出错。**用带重叠的滑窗**（比如 50% overlap）然后做拼接。

## 八、一张速查表

| 概念 | DAW 里的样子 | AI 里的样子 | 最容易错的地方 |
|---|---|---|---|
| 采样率 | 44.1k / 48k | 16k / 22k / 24k / 32k | 不重采样 → 音高错乱 |
| 位深 | 16 / 24 bit | float32，[-1, 1] | 忘归一化 → 输出噪声 |
| 声道 | 立体声 | 单声道为主 | 相位抵消 |
| 表示 | 波形 | log-Mel 频谱图 | n_fft / hop 对不上 |
| 形状 | 不用管 | `[B, C, T]` 或 `[B, F, T]` | 时间轴和频率轴搞反 |
| 响度 | 你手工调 | LUFS 自动标准化 | 电平不匹配导致质量下降 |
| 长度 | 多长都行 | 通常有硬上限 | 硬切导致边界 artifacts |
