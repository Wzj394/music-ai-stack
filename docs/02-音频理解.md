# 02 · 音频理解

> 让机器**听懂**声音：说的是什么、有谁在唱、什么乐器、多快、什么调。

---

## 这一类解决什么问题

| 任务 | 输入 → 输出 | 典型场景 |
|---|---|---|
| **语音识别（ASR）** | 音频 → 文字 | 歌词转写、采访整理、播客字幕 |
| **声源分离（MSS）** | 混音 → 多轨 | 扒伴奏、提取人声、采样 |
| **音乐信息检索（MIR）** | 音频 → 标签/数值 | 测 BPM、调性、和弦、曲式结构 |
| **音频事件检测** | 音频 → 时间标记 | 鼓点检测、段落切分 |
| **人声活动检测（VAD）** | 音频 → 人声区间 | 预处理、自动切割、跳过静音 |

## 每类的实际情况

### ASR：已经被 Whisper 统一了

**现状**：Whisper 之后，通用语音识别基本没悬念。差异只在**怎么跑得更快**和**中文效果怎么调**。

- 追求速度 → **faster-whisper**（CTranslate2 后端，同精度下快很多）
- 没显卡 / 想塞进小设备 → **whisper.cpp**
- 纯中文、要标点和说话人 → **FunASR**

**新手从哪开始**：`faster-whisper`，模型选 `large-v3` 或 `medium`。没显卡就 `small`。

**坑**：

- Whisper 会**幻觉**——静音段或纯音乐段，它可能凭空"生成"字幕。**不要相信它在无语音处的输出。**
- 长音频要自己切片（30 秒窗口），且要处理边界
- 中文标点和断句不完美，后处理常常必要

> 你机器上已装 `faster-whisper` + `ctranslate2`，可以直接用。

### 分离：UVR5 是新手最快的路

**现状**：Demucs 是第一代标杆，**BS-RoFormer 这一系是目前质量天花板**。实际使用里，大家更多通过 **UVR5** 或 **MSST** 这类集成工具去用各种模型，而不是单独跑某一个仓库。

**新手从哪开始**：

- **不写代码** → 装 UVR5（图形界面，选模型点按钮）
- **写代码** → Demucs 的 Python API

**坑**：

- **分离不是无损的**。任何模型都会在输出里留下 artifacts，尤其是镲片、弦乐、混响重的素材
- 母带压得很死的商业作品，分离效果会明显变差
- 分离出来的人声常常带残留伴奏，需要二次处理

### MIR：librosa 通吃八成需求

**现状**：传统 DSP 方法（librosa、Essentia）在节拍、调性这类任务上依然能打，而且快、省、可解释。深度学习主要用在风格分类、结构分析这些语义任务上。

**新手从哪开始**：`librosa`。先学会 `beat_track`、`onset_detect`、`chroma_stft` 这几个。

**坑**：

- **BPM 检测在电子乐以外的曲风上经常错**（尤其是自由速度、变速、复合拍）
- 调性检测对转调歌曲会给出误导结果
- 这些算法大多假设 4/4 拍

### VAD：看起来简单，其实值得单独装一个

**为什么不能自己用能量阈值搞**：音乐会骗过阈值。

Silero VAD 是个小模型，几行就能用，而且比阈值稳得多。

## 组合用法（真实工作流）

这些任务经常串起来用：

```
采访录音
  → VAD 切出说话段
  → ASR 转写
  → 人工校对

翻唱素材
  → 分离出人声
  → 转 MIDI 看旋律
  → 重新编曲

老歌采样
  → 分离出鼓
  → 测 BPM
  → 对齐到工程网格
```
