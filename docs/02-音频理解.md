# 02 · 音频理解

> 让机器**听懂**声音：说的是什么、有谁在唱、什么乐器、多快、什么调。
>
> **核实时间：2026-10-12**（逐仓库查了最后提交日期、归档标记、许可证）

---

## 这一类解决什么问题

| 任务 | 输入 → 输出 | 典型场景 |
|---|---|---|
| **语音识别（ASR）** | 音频 → 文字 | 歌词转写、采访整理、播客字幕 |
| **声源分离（MSS）** | 混音 → 多轨 | 扒伴奏、提取人声、采样 |
| **音乐信息检索（MIR）** | 音频 → 标签/数值 | 测 BPM、调性、和弦、曲式结构 |
| **音频事件检测** | 音频 → 时间标记 | 鼓点检测、段落切分 |
| **人声活动检测（VAD）** | 音频 → 人声区间 | 预处理、自动切割、跳过静音 |

## 一、语音识别（ASR）

| 名称 | 用途 | 链接 | 状态 | 备注 |
|---|---|---|---|---|
| **faster-whisper** | Whisper 的 CTranslate2 重实现 | [SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper) | 🟢 2026-10 | MIT；CPU int8 可跑，**服务端首选** |
| **Whisper** | 多语 ASR 基线 | [openai/whisper](https://github.com/openai/whisper) | 🟢 2026-08 | Apache-2.0；large-v3 约 1.5B，需 GPU |
| **whisper.cpp** | GGML C/C++ 推理 | [ggml-org/whisper.cpp](https://github.com/ggml-org/whisper.cpp) | 🟢 2026-10 | MIT；**端侧/无 Python 环境首选** |
| **WhisperX** | 词级时间戳 + 说话人分离 | [m-bain/whisperX](https://github.com/m-bain/whisperX) | 🟢 2026-09 | **做字幕轴的首选**；依赖 pyannote 权重 |
| **Qwen3-ASR** | 30 语种 + 22 种中文方言，**含歌声与带伴奏歌曲** | [QwenLM/Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR) | 🟢 2026 | Apache-2.0；0.6B/1.7B；**中文开源 ASR 当前最强之一** |
| **FunASR / SenseVoice** | 中文 ASR + 标点 + 热词 + 情感 | [modelscope/FunASR](https://github.com/modelscope/FunASR) | 🟢 2026-10 | 中文工程化最完整 |
| **sherpa-onnx** | 端侧部署（C/Java/Swift 绑定） | [k2-fsa/sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) | 🟢 2026-10 | Apache-2.0；**落地部署的事实标准** |
| **ESPnet / SpeechBrain** | 语音研究训练框架 | [espnet](https://github.com/espnet/espnet) · [speechbrain](https://github.com/speechbrain/speechbrain) | 🟢 2026-10 | 适合复现论文，不适合做产品 |
| **Vosk** | 老牌离线小模型 | [alphacep/vosk-api](https://github.com/alphacep/vosk-api) | 🟢 2026-08 | 精度已被取代 |

> **已归档**：Kaldi（2025-09 放缓，被 k2/icefall、NeMo 取代）

### 说明

**主流**：多用 `faster-whisper` 或 `whisper.cpp`；中文优先 **Qwen3-ASR**（方言、歌声、带 BGM 全覆盖）或 FunASR；要字幕轴再加 WhisperX 或 Qwen3-ForcedAligner。

**新手**：`whisper.cpp` → 配 Silero VAD 切句 → 中文方言/热词需求换 FunASR / Qwen3-ASR。

**坑**：

- **Whisper 在静音和音乐段会幻觉出整句文本**，必须配 VAD
- 时间戳是**段落级不是词级**
- 中文要按 CER 评测，标点与数字规范化各模型差异很大

## 二、声源分离（MSS）

| 名称 | 用途 | 链接 | 状态 | 备注 |
|---|---|---|---|---|
| **adefossez/demucs** | Demucs v4 作者**实际开发仓** | [adefossez/demucs](https://github.com/adefossez/demucs) | 🟢 2026-08 | MIT；**要用 Demucs 指向这里** |
| **facebookresearch/demucs** | 官方旧仓 | [facebookresearch/demucs](https://github.com/facebookresearch/demucs) | 🟡 2023-11 | 模型仍被大量引用，但主仓已停 |
| **UVR5** | 图形化分离，集成大量社区权重 | [Anjok07/ultimatevocalremovergui](https://github.com/Anjok07/ultimatevocalremovergui) | 🟢 2026-10 | **不写代码就能用**；权重许可需逐个溯源 |
| **BS-RoFormer** | 分离 SOTA 架构参考实现 | [lucidrains/BS-RoFormer](https://github.com/lucidrains/BS-RoFormer) | 🟢 2026-06 | MIT（代码）；权重另有许可 |
| **Mel-Band RoFormer 推理** | 直接跑 Mel-Band RoFormer 权重 | [openmirlab/melband-roformer-infer](https://github.com/openmirlab/melband-roformer-infer) | 🟢 | **2025-2026 人声分离常用路线** |
| **python-audio-separator** | 命令行/批量分离，统一集成 MDX/RoFormer | [nomadkaraoke/python-audio-separator](https://github.com/nomadkaraoke/python-audio-separator) | 🟢 2026-10 | **适合脚本化生产** |
| **Music-Source-Separation-Training** | 分离模型训练/微调框架 | [ZFTurbo/Music-Source-Separation-Training](https://github.com/ZFTurbo/Music-Source-Separation-Training) | 🟢 2026-09 | **自训模型首选脚手架** |
| **Spleeter** | 早期四轨分离，开创性 | [deezer/spleeter](https://github.com/deezer/spleeter) | 🟡 2026-06 零星提交 | MIT；**未归档，但质量已被超越** |
| **Open-Unmix / Asteroid** | 经典基线与研究工具箱 | [open-unmix](https://github.com/sigsep/open-unmix-pytorch) · [asteroid](https://github.com/asteroid-team/asteroid) | Unmix 🟡 · Asteroid 🟢 | 教学与 baseline 用 |

### 说明

**主流**：质量优先用 **Mel-Band / BS-RoFormer 系权重**（经 UVR5 或 audio-separator 调用），通用性用 Demucs。

**实用组合**：`python-audio-separator 脚本 + RoFormer 权重`

**新手**：UVR5 图形界面零代码，或 `python-audio-separator` 一条命令。

**坑**：

- **许可证是最大坑** —— 大量 SOTA 权重仅限非商用，UVR5 打包的权重来源不统一
- 分离质量对**采样率、立体声相位、chunk overlap** 极敏感
- 分离后的 artifacts 直接拿去训下游模型会**污染数据**

## 三、音乐信息检索（MIR）

| 名称 | 用途 | 链接 | 状态 | 备注 |
|---|---|---|---|---|
| **librosa** | 加载/特征/节拍/音高基础库 | [librosa/librosa](https://github.com/librosa/librosa) | 🟢 2026-10 | ISC；**MIR 代码的地基**；API 跨版本有变动 |
| **Essentia** | 工业级特征 + 预训练模型 | [MTG/essentia](https://github.com/MTG/essentia) | 🟢 2026-10 | ⚠️ **AGPL-3.0，商用需商业授权** |
| **Beat This!** | 节拍与 downbeat 检测 SOTA | [CPJKU/beat_this](https://github.com/CPJKU/beat_this) | 🟢 2026-05 | **2024 年起取代 madmom 成为节拍首选** |
| **madmom** | 节拍/起音/和弦经典实现 | [CPJKU/madmom](https://github.com/CPJKU/madmom) | 🟡 2024-08 | 对新 Python/NumPy 兼容差，装环境易翻车 |
| **MERT** | 音乐理解自监督表征 | [m-a-p/MERT-v1-330M](https://huggingface.co/m-a-p/MERT-v1-330M) | 🟡 2025-05 | ⚠️ CC-BY-NC-4.0（**非商用**）；微调常见起点 |
| **MuQ** | 音乐表征（Mel 残差 VQ） | [tencent-ailab/MuQ](https://github.com/tencent-ailab/MuQ) | 🟢 2025-08 | 配套 MuQ-MuLan 做文本-音乐检索 |
| **MusicFM** | 音乐基础模型（掩码建模） | [minzwon/MusicFM](https://github.com/minzwon/MusicFM) | 🟡 2024-02 | MIT |
| **CLAP（LAION）** | 音频-文本对比学习，零样本标签/检索 | [LAION-AI/CLAP](https://github.com/LAION-AI/CLAP) | 🟡 2025-05 | Apache-2.0 |
| **music21** | 乐谱/MIDI 符号层分析与转换 | [cuthbertLab/music21](https://github.com/cuthbertLab/music21) | 🟢 2026-10 | BSD；**符号分析必备**，速度慢 |
| **All-in-One** | 一个模型做标签/流派/情绪/乐器 | [mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one) | 🟡 2023-10 | 已被更新的自监督模型超越 |
| **mir_eval** | 评测指标标准实现 | [mir-evaluation/mir_eval](https://github.com/mir-evaluation/mir_eval) | 🟢 2026-02 | **写论文对比结果的必用件** |
| **MSAF** | 音乐结构分析框架 | [urinieto/msaf](https://github.com/urinieto/msaf) | 🟢 2026-03 | |

### 说明

**主流**：特征层用 librosa；模型层用自监督表征（MERT / MuQ / MusicFM）+ 小分类头微调；**节拍用 Beat This!**；标签/情绪用 Essentia 预训练模型最省事。

**新手**：librosa 教程 → 用 mir_eval 看懂指标 → 再决定提特征还是上预训练模型。

**坑**：

- ⚠️ **Essentia 是 AGPL**，闭源产品用会触发开源义务
- **madmom 在新环境常装不上**
- MERT / MusicFM 权重多为 **CC-BY-NC，商用模型不能直接用**
- MIR 数据集小，微调极易过拟合，**必须用官方 split**

## 四、人声活动检测（VAD）/ 音频事件检测

| 名称 | 用途 | 链接 | 状态 | 备注 |
|---|---|---|---|---|
| **Silero VAD** | 轻量高精度 VAD（ONNX，<2MB） | [snakers4/silero-vad](https://github.com/snakers4/silero-vad) | 🟢 2026-09 | MIT；**实时与批处理事实标准** |
| **pyannote-audio** | 说话人分离 + VAD | [pyannote/pyannote-audio](https://github.com/pyannote/pyannote-audio) | 🟢 2026-06 | MIT 代码；权重需接受 HF 条款 |
| **TEN VAD** | 低延迟流式 VAD | [TEN-framework/ten-vad](https://github.com/TEN-framework/ten-vad) | 🟢 2026-10 | Apache-2.0；实时语音 Agent |
| **FireRedVAD** | 中文场景 VAD | [FireRedTeam/FireRedVAD](https://github.com/FireRedTeam/FireRedVAD) | 🟢 2026-05 | Apache-2.0 |
| **BEATs / CED** | 更新的音频表征与事件检测 | [microsoft/unilm](https://github.com/microsoft/unilm) · [RicherMans/CED](https://github.com/RicherMans/CED) | 🟢 | **事件检测用这个，不要从头训 CNN** |
| **PANNs / AST** | AudioSet 预训练事件分类 | [audioset_tagging_cnn](https://github.com/qiuqiangkong/audioset_tagging_cnn) · [ast](https://github.com/YuanGongND/ast) | 🔴 2021 / 2023 | 经典基线，已停止更新 |

### 说明

**主流**：VAD 一律 Silero（中文用 FireRedVAD，实时用 TEN VAD）；事件检测用 BEATs / CED 表征接分类头。

**新手**：Silero 的 `get_speech_timestamps` 三行代码即可。

**坑**：

- **VAD 阈值决定下游一切** —— 切太碎毁 ASR 上下文，切太粗带进音乐
- pyannote 权重需 HF 登录并接受条款
- AudioSet 标签是**层级结构**，当扁平多标签用会得到很差结果

## 组合用法（真实工作流）

```
采访录音
  → VAD 切出说话段（Silero）
  → ASR 转写（faster-whisper / Qwen3-ASR）
  → 人工校对

翻唱素材
  → 分离出人声（Mel-Band RoFormer）
  → 转 MIDI 看旋律（见 05）
  → 重新编曲

老歌采样
  → 分离出鼓
  → 测 BPM（Beat This!）
  → 对齐到工程网格
```
