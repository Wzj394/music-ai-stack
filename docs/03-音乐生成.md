# 03 · 音乐生成

> 从文字、音频或符号生成音乐。
> **核实时间：2026-10-12** —— 这是变化最快的一个方向，本文的每个条目都查过最后提交日期和许可证。

---

## 这类任务的三种形态

| 形态 | 输入 → 输出 | 生成的产物 | 你能拿来干嘛 |
|---|---|---|---|
| **文本生音乐** | 文字描述 → 音频 | 波形 | 找灵感、做 BGM、音效 |
| **音频编辑 / 续写** | 一段音频 → 修改后的音频 | 波形 | 补全动机、改段落、加轨 |
| **符号音乐生成** | 文字/条件 → MIDI | MIDI | **可以直接在 DAW 里改** |

---

## ⚠️ 2026 年最重要的一件事：许可证

**这是分水岭，先看这个再选模型。**

| 许可证 | 代表项目 | 能不能商用 |
|---|---|---|
| **MIT / Apache-2.0** | ACE-Step 1.5、HeartMuLa | ✅ **可以** |
| **社区许可 / 自定义** | Stable Audio 3 | ⚠️ 有条款限制，需细读 |
| **CC-BY-NC**（非商用） | MusicGen、YuE2 | ❌ **商用直接违规** |

> **MusicGen 虽然最出名，但它的权重是 CC-BY-NC。** 想做商业项目，直接看 **ACE-Step 1.5**（MIT）。
> 这是 2026 年开源音乐生成领域最大的变化。

## 一、文本生音乐 / 音频生成

| 名称 | 用途 | 链接 | 状态 | 许可证 | 备注 |
|---|---|---|---|---|---|
| **ACE-Step 1.5** | LM 规划 + DiT 生成的开源音乐基础模型 | [ace-step/ACE-Step-1.5](https://github.com/ace-step/ACE-Step-1.5) | 🟢 2026-08 | ✅ **MIT** | ⭐ **首选**：2B/4B DiT + LM，**<4GB 显存可跑**，50+ 语言歌词，支持 cover / repaint / 续写 / 分轨 / 多轨 / LoRA，**附 VST3** |
| **Stable Audio 3** | 开放权重音乐/音效生成与**音频编辑** | [Stability-AI/stable-audio-3](https://github.com/Stability-AI/stable-audio-3) | 🟢 2026-10 | ⚠️ Stability Community License | 44.1kHz 立体声；small 433M 可 CPU，medium 1.4B 需 GPU；text→audio、audio→audio、inpainting、LoRA |
| **HeartMuLa（heartlib）** | 歌词+标签条件的音乐基础模型族 | [HeartMuLa/heartlib](https://github.com/HeartMuLa/heartlib) | 🟢 2026 | ✅ **Apache-2.0** | 含 HeartMuLa（3B LM）、HeartCodec（12.5Hz / 48kHz 立体声）、HeartTranscriptor、HeartCLAP |
| **YuE / YuE2** | 歌词驱动的歌曲生成（**含人声**） | [multimodal-art-projection/YuE](https://github.com/multimodal-art-projection/YuE) | 🟢 2026-10 | ❌ CC-BY-NC-4.0 | 中文歌词支持较好；**不能商用** |
| **MusicGen / AudioCraft** | 影响最大的一代 | [facebookresearch/audiocraft](https://github.com/facebookresearch/audiocraft) | 🟡 2025-03 | ❌ 权重 CC-BY-NC-4.0 | 代码 MIT；已被 ACE-Step / Stable Audio 3 超越 |
| **ACE-Step v1** | 前代开源音乐生成 | [ace-step/ACE-Step](https://github.com/ace-step/ACE-Step) | 🟢 2026-02 | Apache-2.0 | 已被 1.5 取代 |
| **DiffRhythm** | 全曲快速生成 | [ASLP-lab/DiffRhythm](https://github.com/ASLP-lab/DiffRhythm) | 🟡 2025-11 | 未核实 | 长曲一致性一般 |
| **InspireMusic** | 音乐/歌曲生成工具箱 | [FunAudioLLM/InspireMusic](https://github.com/FunAudioLLM/InspireMusic) | 🟡 2025-05 | — | 阿里 FunAudioLLM 出品 |
| **stable-audio-tools** | Stable Audio 训练/微调框架 | [Stability-AI/stable-audio-tools](https://github.com/Stability-AI/stable-audio-tools) | 🟢 2026-05 | — | 基础研究向 |
| **Riffusion** | 频谱图扩散（思路有趣） | [riffusion/riffusion](https://github.com/riffusion/riffusion) | 🟡 | — | 实用性一般 |

> **状态未核实**：SongGeneration（腾讯）—— 官方 GitHub 仓 404，HF 页返回 401，疑似门控或下架。

### 说明

**主流**：

- **本地生成默认 ACE-Step 1.5** —— MIT、消费级显卡、功能最全，这是 2026 年的答案
- **音效 / 短素材 / 编辑** 用 Stable Audio 3（它的 `init_audio` + `inpaint_mask_*` 是最直接的续写 API）
- **歌词可控 + 中文** 再对比 HeartMuLa / YuE2

**续写与风格迁移**：Stable Audio 3 的 inpainting 最直接；ACE-Step 1.5 的 cover / repaint / extract / lego 覆盖「加轨 / 改写」工作流。

**坑**：

- **许可证**（见上面那节）—— 这是最容易出事的地方
- **采样率不统一**（32kHz vs 44.1kHz），与 DAW 素材混合必须重采样
- **带人声的完整歌曲仍是开源弱项**，多数模型只擅长器乐 loop

## 二、符号音乐生成（MIDI 层面）

| 名称 | 用途 | 链接 | 状态 | 备注 |
|---|---|---|---|---|
| **MidiTok** | MIDI 分词（给 Transformer 用） | [Natooz/MidiTok](https://github.com/Natooz/MidiTok) | 🟢 2026-09 | MIT；**符号生成的必备中间层** |
| **Magenta RealTime** | 实时音乐生成模型 | [magenta/magenta-realtime](https://github.com/magenta/magenta-realtime) | 🟢 2026-07 | Google 现行主线 |
| **NotaGen** | LLM 训练范式的符号音乐生成 | [ElectricAlexis/NotaGen](https://github.com/ElectricAlexis/NotaGen) | 🟢 | 生成古典风格乐谱；许可未核实 |
| **Text2MIDI** | 文本 → MIDI | [AMAAI-Lab/Text2midi](https://github.com/AMAAI-Lab/Text2midi) | 🟡 2025-02 | 研究向 |
| **muspy** | 符号音乐数据处理 | [salu133445/muspy](https://github.com/salu133445/muspy) | 🟡 2024-01 | |
| **Magenta** | 符号音乐生成元老工具箱 | [magenta/magenta](https://github.com/magenta/magenta) | 🔴 **已归档 2026-01** | 代码仍有参考价值 |

### 说明

**主流**：符号生成现在走「**MIDI 分词（MidiTok）+ LLM/Transformer**」路线，而不是 MuseGAN 时代的 GAN。

**新手**：用 `music21` / `pretty_midi` 做好数据清洗与表示，再决定训不训模型。

**坑**：

- MIDI 表示法**本身没有标准**（REMI、CPWord、Octuple 各有取舍），换表示法常导致结果不可比
- **符号生成几乎没有商用级开源权重**，产出通常需要人工编配
- 实用性目前仍不如音频生成

## 新手从哪开始

```
第 1 步：跑通 ACE-Step 1.5 的最小例子
         → MIT 许可，消费级显卡，是目前最没坑的起点

第 2 步：拿你自己的素材做续写 / 编辑
         → Stable Audio 3 的 audio-to-audio 比文字生成更容易出有用的结果

第 3 步：把生成结果导入 REAPER
         → 建立"生成 → 使用"的完整链路
         → ACE-Step 1.5 有 VST3，可以直接挂进宿主试

第 4 步：需要精细控制时，转向符号生成
         → MidiTok + 自己训，或先用 music21 手工处理
```

**别一上来就下 30GB 的模型。** 先用小模型确认工作流通不通。

---

## 坑清单

| 坑 | 说明 |
|---|---|
| **许可证** | 见本文开头。这是最容易出事的地方 |
| **显存** | 长音频生成对显存要求陡增；ACE-Step 1.5 官方称 <4GB 可跑，但长曲仍需更多 |
| **采样率不匹配** | 生成的是 32k，你要 48k，直接重采样会有高频损失 |
| **种子不可复现** | 同一个 prompt 两次结果不同，想复现要固定 seed |
| **提示词玄学** | 官方文档的 prompt 写法和实际效果常有差距，靠自己试 |
| **生成即巅峰** | 第一次跑出来的 demo 效果往往最好，别被 demo 骗了 |
