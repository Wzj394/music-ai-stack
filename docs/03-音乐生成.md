# 03 · 音乐生成

> 从文字、音频或符号生成音乐。这是变化最快的一个方向 —— **本文的核实时间是 2026-10，请务必自己去 GitHub 确认现状。**

---

## 这类任务的三种形态

| 形态 | 输入 → 输出 | 生成的产物 | 你能拿来干嘛 |
|---|---|---|---|
| **文本生音乐** | 文字描述 → 音频 | 波形 | 找灵感、做 BGM、音效 |
| **音频续写 / 变奏** | 一段音频 → 更长的音频 | 波形 | 补全动机、扩展 loop |
| **符号音乐生成** | 文字/条件 → MIDI | MIDI | **可以直接在 DAW 里改** |

**最后一种常被忽视，但对做音乐的人最实用** —— 因为 MIDI 你能改，波形你改不动。

## 实际情况

### 这个领域「半年前的经验」就可能作废

2023 年 MusicGen 是标杆，2024-2025 涌现了一大批，到 2026 年已经有好几个能生成**带人声的完整歌曲**的模型了。

**所以这个文档的写法是**：告诉你**怎么判断**，而不是给你一份会被淘汰的排行榜。

判断一个音乐生成模型值不值得投入，按这个顺序看：

1. **能生成多长** —— 10 秒 loop 和 3 分钟完整歌曲，是两个量级的难度
2. **有没有人声** —— 纯器乐和有歌词演唱，差别很大
3. **许可协议** —— 很多模型权重是「非商用」，做商业项目前务必看清
4. **算力要求** —— 有些模型消费级显卡根本跑不动
5. **最后 commit 时间** —— 比 star 数有用

### 生成出来的东西能用吗

**老实说：当成「素材生成器」可以，当成「作曲」还差得远。**

实际好用的场景：

- 找一个**音色/氛围**，然后自己重新编曲
- 生成**过渡音效**、环境声
- 生成大量变体，挑一个当**采样**
- 卡壳时听点不一样的**打破思维定式**

不好用的场景：

- 指望它直接产出能发的成品
- 需要精确控制（"第 3 小节加个转位"）
- 需要长结构一致性（副歌要跟主歌呼应）

### 符号音乐生成：最被低估的方向

如果你要的是**能改的东西**，MIDI 生成比波形生成实用得多：

- 生成 → 导入 DAW → 换成你自己的音色 → 改
- 完全可控，不会被模型"锁死"

**但这条路目前成熟度不如波形生成**，工具少、效果参差。这也是个机会。

## 新手从哪开始

```
第 1 步：跑通 MusicGen 的最小例子
         → 感受一下"文字变音乐"是什么体验
         → 用最小的模型，别一上来就下大的

第 2 步：拿你自己的素材做音频续写
         → 比文字生成更容易出有用的结果

第 3 步：把生成结果导入 REAPER
         → 建立"生成 → 使用"的完整链路

第 4 步：再去看那些更大的模型
         → 这时候你知道自己要什么了
```

**别一上来就下 30GB 的模型。** 先用小模型确认工作流通不通。

## 坑清单

| 坑 | 说明 |
|---|---|
| **许可协议** | 很多权重禁止商用。用之前看清楚，别做完项目才发现 |
| **显存** | 长音频生成对显存要求陡增，24GB 都不一定够 |
| **采样率不匹配** | 生成的是 32k，你要 48k，直接重采样会有高频损失 |
| **种子不可复现** | 同一个 prompt 两次结果不同，想复现要固定 seed |
| **提示词玄学** | 官方文档的 prompt 写法和实际效果常有差距，靠自己试 |
| **生成即巅峰** | 第一次跑出来的 demo 效果往往是最好的，别被 demo 骗了 |
