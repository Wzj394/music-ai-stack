# 07 · 数据集

> 训练和评测要用。**这一篇的重点不是"有哪些"，而是"哪些不能用、哪些有坑"。**
>
> **核实时间：2026-10-12**

---

## ⚠️ 用数据集前必须确认的三件事

| 事项 | 为什么重要 |
|---|---|
| **许可协议** | 很多数据集「可以研究，不能商用」。用错后果严重 |
| **版权来源** | 有些是从流媒体/YouTube 抓的，**本身就侵权** |
| **标注质量** | 有些经典数据集有已知错误，论文里被反复批评 |

> **一个残酷的事实**：音乐领域很多流行数据集，版权状态是模糊甚至明确有问题的。
> 拿它们训出来的模型，**商用发布时会继承这个风险**。

### 一句话结论（先看这个）

**以下都是非商用**，别拿去做商业产品：

```
MUSDB18 · MAESTRO · M4Singer · GTSinger · ESC-50
```

**以下音频许可按条混合**，训练商用模型有实质法律风险：

```
AudioSet · MTG-Jamendo · FMA
```

**以下需要签协议**，直接分发违规：

```
WenetSpeech
```

## 实际情况

### 版权是一颗定时炸弹

| 类型 | 版权状态 |
|---|---|
| **合成/渲染的**（Slakh） | ✅ 干净 |
| **众包授权**（Common Voice、部分 FMA） | ✅ 相对干净 |
| **学术收集、标注清晰**（MUSDB18） | 🟡 通常限制研究用途 |
| **从流媒体/YouTube 抓的** | 🔴 **高风险** |

**结论**：如果打算做商业产品，能用的数据集比想象中少得多。

### 标注质量参差不齐

- GTZAN 被反复证明有重复和错标，但因为它太老、引用太多，还在被用
- 大规模自动标注的数据集（比如用模型给 YouTube 打标签）**误差是系统性的**
- MIDI 数据集普遍清洗不足（乐器错、时值错、缺拍号）
- **HuggingFace 上不少是第三方转载，版本与官方不一致**

**自己抽查是必须的**。随机抽 20 个样本听一遍/看一眼，比看论文里的指标有用。

### 规模和质量的权衡

```
小而干净  ←——————————————→  大而脏
MUSDB18              AudioSet / 各种爬来的
     ↑                        ↑
  能出可信结论            能训出"能跑"的模型
```

**新手建议**：先用小而干净的做验证，规模问题后面再说。

## 怎么自己造数据集

现实里，**你自己的素材往往比公开数据集更有价值**：

| 来源 | 注意 |
|---|---|
| 自己的作品分轨 | ✅ 版权干净，风格统一 |
| 自己录的素材 | ✅ 最干净 |
| 明确授权的音源库 | ✅ 保留授权凭证 |
| 购买的素材包 | ⚠️ 看清 EULA，很多禁止用于训练 |

> **如果你有多年积累的工程文件（分轨、MIDI、采样）——
> 那是你最大的资产，比任何公开数据集都值钱。**

## 坑清单

| 坑 | 说明 |
|---|---|
| **只看论文指标就选数据集** | 论文的评测条件和你的场景可能完全不同 |
| **不看许可** | 做完才发现不能商用 |
| **不抽查** | 20 个样本能发现的问题，训练完就晚了 |
| **HF 上抓到第三方转载** | 版本与官方不一致，许可也可能被改过 |
| **采样率不统一** | 混用多个数据集时格式必须统一（见 [01](01-音频基础.md)） |
| **类别不平衡** | 某种乐器/语言样本极少，模型学不会 |
| **数据泄漏** | 训练集和测试集有重叠，指标虚高 |
