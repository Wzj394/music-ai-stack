# 08 · 学习路径

> **主观建议，不是唯一答案。** 这篇讲"按什么顺序学不容易劝退"。
> **最后核实：2026-10**

---

## 先认清一件事

音乐 AI 这个领域有两拨人，学法完全不同：

| 你是 | 你的优势 | 你的短板 | 该怎么走 |
|---|---|---|---|
| **做音乐的** | 听得出好坏，懂工作流，知道要什么 | 代码、环境配置 | **从 DAW 集成切入**，让 AI 服务于你已有的流程 |
| **写代码的** | 装环境、调库、读论文 | 听不出问题，不知道需求 | **从音频基础补起**，多找音乐人听你的结果 |
| **两头都沾** | 最快 | 容易贪多 | 挑一个方向做深，别铺开 |

**下面主要写给「做音乐的」。** 做代码的可以把顺序反过来。

---

## 核心原则：别从工具表开始

`stack/工具总表.md` 有上百个条目。**一上来就看它，你会淹死，然后什么都没做。**

正确的顺序是：

```
先想清楚"我要解决什么具体问题"
    ↓
找那个问题上最成熟的工具（可能只有一个）
    ↓
跑通它
    ↓
写笔记
    ↓
再想下一个问题
```

**永远从"问题"出发，不是从"工具"出发。**

## 阶段路线

### 阶段 0：地基（约 1-2 周）

**目标**：搞清楚音频在 AI 里长什么样。

- 读 [01-音频基础.md](01-音频基础.md)
- 装好 Python 环境（你已经装了一堆，确认能用哪个就行）
- 会用 `librosa` 读一个文件、看形状、画个频谱图

**验收**：能说出下面这些的答案

- 我的音频是 48k 立体声，模型要 16k 单声道，怎么转？
- 频谱图的形状 `[1025, 时间帧]` 里，1025 是怎么来的？
- `log-Mel` 是什么，为什么大家用它？

> **别跳过这一步。** 后面 90% 的诡异 bug 都藏在这里。

### 阶段 1：跑通一个完整的链（约 2-4 周）

**目标**：从"输入音频"到"能在 DAW 里用的结果"，完整走一遍。

**推荐选这个任务**：`转写 → 修 → 导入 DAW`

```
1. 找一段干净的钢琴或吉他独奏
2. 用 Basic Pitch 转 MIDI        → docs/05
3. 导入 REAPER，量化
4. 手工修几个明显错的音符
5. 换成你自己喜欢的音色
```

**为什么选它**：

- 中间没有黑盒（你能听见每一步的结果）
- 立刻能用在真实工作里
- 门槛低，不会卡在显存上

**验收**：能把这个流程重复做三次，且知道每步大概要多久。

### 阶段 2：接入自动化（约 2-4 周）

**目标**：把阶段 1 的手工操作变成一条命令。

- 读 [06-DAW集成与自动化.md](06-DAW集成与自动化.md)
- 学 ReaScript 基础（Lua 或 Python）
- 把阶段 1 的流程写成一个脚本

**验收**：丢一个文件夹进去，出来一批 MIDI。

> 到这一步，你已经比 90% 只会点网页 Demo 的人强了。

### 阶段 3：挑一个方向深入

到这里你该知道自己对什么感兴趣了。路线举例：

| 兴趣 | 深入方向 |
|---|---|
| **扒歌、编曲** | 提升转写质量：分离 → 转写 → 多轨对齐 |
| **做伴奏** | 音源分离 + 重混音，[02](02-音频理解.md) |
| **探索音色** | 音乐生成，[03](03-音乐生成.md) |
| **人声** | SVC / TTS，[04](04-人声与歌声.md)（先读伦理那节） |
| **做工具** | 把流程打包成工具给别人用 |

### 阶段 4：看论文、跟社区

**这时候才该看论文** —— 因为你现在能判断哪篇有用。

- 跟 HuggingFace 上的音频模型趋势
- 订阅几个活跃的 GitHub 仓库的 release
- 参加相关社区（Discord / Reddit r/MachineLearning 等）

## 时间预算的现实预期

| 阶段 | 乐观 | 现实 |
|---|---|---|
| 阶段 0 | 3 天 | 1-2 周 |
| 阶段 1 | 1 周 | 2-4 周 |
| 阶段 2 | 2 周 | 1-2 个月 |
| 阶段 3 | 持续 | 持续 |

**注意**：真正花时间的不是"跑模型"，是：

- 环境配置（版本冲突、CUDA、依赖地狱）
- 数据准备（找素材、清洗、转格式）
- 调参和试错
- 处理边缘情况

**跑模型本身可能只占 10% 的时间。**

## 别做的事

| ❌ 别做 | 为什么 |
|---|---|
| **一上来就下 30GB 模型** | 先确认工作流通不通，再考虑规模 |
| **同时学三个方向** | 每个都浅尝辄止，等于没学 |
| **不看官方 README 只看别人教程** | 教程会过期，README 是最新的 |
| **跳过音频基础** | 后面会以十倍的代价补回来 |
| **在环境配置上死磕三天** | 超过 2 小时搞不定的环境问题，换个方案 |
| **只看不动手** | 这个领域"看会了"和"跑通了"差十万八千里 |
| **不留笔记** | 三个月后你完全不记得当时怎么解决的 |

## 怎么判断自己真的学会了

**不是"我能跑通 demo"，而是**：

- [ ] 出错时我知道去哪看日志，而不是干瞪眼
- [ ] 我能解释每一步在干什么，不只是复制粘贴
- [ ] 换一个素材，我不需要重新查教程
- [ ] 我能把流程讲给别人听，别人能照着做
- [ ] 我知道这个工具的**局限**在哪

---

## 给「做音乐的」最后一句

> **你的耳朵是稀缺资源，不是代码能力。**

这个领域现在最不缺会调库的人，最缺的是**能判断结果好坏的人**。

一个做音乐的人听到 AI 输出说"这个鼓的瞬态糊了"——这句话的价值，比会跑十个模型高得多。

**所以别被代码吓到。你的判断力才是壁垒。**
