## 一、开源音乐生成终于有了「能商用」的选择

### ⭐ ACE-Step 1.5

[ace-step/ACE-Step-1.5](https://github.com/ace-step/ACE-Step-1.5) · **MIT 许可**

这是 2026 年开源音乐生成最大的变化。

| | |
|---|---|
| **架构** | 2B/4B DiT + 0.6B/1.7B/4B LM（LM 做规划，DiT 做生成） |
| **硬件** | 官方称 **<4GB 显存可跑**；A100 上单曲 <2 秒 |
| **能力** | 50+ 语言歌词，cover / repaint / 续写 / 分轨 / 多轨 / LoRA |
| **彩蛋** | **附 VST3 插件，可以直接挂进 DAW** |

**为什么重要**：在此之前，主流开源音乐生成模型（MusicGen、YuE）的权重都是 **CC-BY-NC（非商用）**。ACE-Step 1.5 用 MIT 把这条路打开了 —— **本地跑、消费级显卡、能商用**，三件事同时成立。

技术报告：arXiv:2602.00744

## 二、音频生成从「生成」转向「编辑」

### Stable Audio 3

[Stability-AI/stable-audio-3](https://github.com/Stability-AI/stable-audio-3) · Stability Community License

| | |
|---|---|
| **规格** | small 433M（CPU/CoreML/TFLite 可跑）、medium 1.4B（需 GPU）、large 仅 API |
| **采样率** | 44.1kHz 立体声 |
| **能力** | text→audio、**audio→audio 编辑**、inpainting / 续写、LoRA |

**为什么重要**：它的定位不是"整曲生成"，而是**音频编辑** —— 给你一段素材，改一段、补一段。
对做音乐的人来说，这比"从零生成一首歌"实用得多。

技术报告：arXiv:2605.17991

## 三、完整音乐基础模型族：HeartMuLa

[HeartMuLa/heartlib](https://github.com/HeartMuLa/heartlib) · **Apache-2.0**

不是一个模型，是**一整套**：

| 组件 | 作用 |
|---|---|
| **HeartMuLa** | 3B LM，歌词 + 标签条件生成 |
| **HeartCodec** | 12.5Hz / 48kHz 立体声音频编解码 |
| **HeartTranscriptor** | 歌词转写 |
| **HeartCLAP** | 音频-文本对齐 |
| **MuLaCover** | 翻唱 / remix |

团队称内部 7B 版本接近 Suno（**未经独立验证**）。

技术报告：arXiv:2601.10547

## 四、中文 ASR 一次补齐：Qwen3-ASR

[QwenLM/Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR) · **Apache-2.0**

| | |
|---|---|
| **规格** | 0.6B / 1.7B |
| **覆盖** | 30 语种 + **22 种中文方言** |
| **杀手特性** | 官方评测显示**可直接转写歌声与带 BGM 的歌曲** |
| **配套** | Qwen3-ForcedAligner-0.6B 出词/字级时间戳 |

**为什么重要**：以往"中文 + 方言 + 唱歌 + 时间戳"要拼好几个模型，现在一个搞定。
做**歌词轴类应用**（自动字幕、卡拉OK、歌词对齐）的关键组件。

技术报告：arXiv:2601.21337

## 五、音频 → MIDI 可能被改写：MuScriptor

[muscriptor/muscriptor](https://github.com/muscriptor/muscriptor) · Kyutai × Mirelo
⚠️ 代码 MIT，**权重 CC-BY-NC-4.0 且需 HF 登录**

| | |
|---|---|
| **训练规模** | 17 万首歌 |
| **规格** | small 103M / medium 307M / large 1.4B（**小模型可 CPU 跑**） |
| **输出** | 含乐器信息的 MIDI |
| **缺点** | **不保留力度** |

**为什么重要**：音频转 MIDI 长期碎片化（basic-pitch 通用但粗糙，Transkun 只做钢琴）。
MuScriptor 是第一个「大规模多乐器」的方案。**但注意非商用许可。**

技术报告：arXiv:2607.08168

## 六、不训练就能换音色唱歌：SoulX-Singer

[Soul-AILab/SoulX-Singer](https://github.com/Soul-AILab/SoulX-Singer) · **Apache-2.0**

零样本高保真歌声合成。在 SVS 长期被 DiffSinger 生态主导（要训练声库）的局面下，
提供了「**不训练直接换音色唱歌**」的路线。

权重：[Soul-AILab/SoulX-Singer](https://huggingface.co/Soul-AILab/SoulX-Singer)

## 七、生态版图变化（**这一节最容易踩坑**）

### 搬到 Codeberg 的

| 项目 | 新地址 | 说明 |
|---|---|---|
| **ReaPack** | [codeberg.org/cfillion/reapack](https://codeberg.org/cfillion/reapack) | GitHub 原仓**已归档** |
| **Tidal** | [codeberg.org/uzu/tidal](https://codeberg.org/uzu/tidal) | 原仓标注 MOVED TO CODEBERG |
| **Strudel** | [codeberg.org/uzu/strudel](https://codeberg.org/uzu/strudel) | 同上 |

> ⚠️ 这三个"看起来还在 GitHub 上活着"的仓库，实际**已经归档**。
> 照着老链接去提 Issue 是不会有回应的。

### 已归档的

| 项目 | 归档时间 | 替代 |
|---|---|---|
| **Magenta** | 2026-01 | [magenta/magenta-realtime](https://github.com/magenta/magenta-realtime) |
| **so-vits-svc** | 2023-10 | RVC / Applio |
| **Seed-VC** | 2025-04 | kNN-VC（零样本） |
| **字节 piano_transcription** | 2022-03 | Transkun / YourMT3 |
| **Microsoft MuZic** | — | — |

### API 进入弃用流程的

**torchaudio** 仓库仍活跃，但 **I/O 与部分后端 API 已标记弃用**，
官方推动迁移到 [pytorch/torchcodec](https://github.com/pytorch/torchcodec)。

> 照抄两年前的教程会踩 deprecation 甚至报错。**新代码直接用 torchcodec 或 soundfile。**

## 八、常见认知纠错

这几条和"普遍印象"不符，值得记住：

| 普遍印象 | 实际 |
|---|---|
| Demucs 看 `facebookresearch/demucs` | ❌ 那个 2023-11 后无提交。**真正在维护的是 [adefossez/demucs](https://github.com/adefossez/demucs)** |
| Spleeter 已经死了 | 🟡 **并未归档**（2026-06 仍有提交），只是质量被 RoFormer 系超越 |
| reapy 能用来遥控 REAPER | ❌ **2021-02 就停止维护了**，别用 |
| ReaPack 在 GitHub 上 | ❌ **已迁 Codeberg** |
| torchaudio 一切正常 | ⚠️ 仓库活跃，但 **I/O API 在弃用中** |
| MusicGen 是首选 | ⚠️ **权重 CC-BY-NC，不能商用**。商用看 ACE-Step 1.5 |
